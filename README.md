# wintag

Docker コンテナで動く GUI アプリのウィンドウを、起動元のコンテナごとに見分けられるようにするツールです。

複数の Docker コンテナで同じアプリ（例：rviz）を動かすと、GNOME Dock 上では 1 つのアイコンにまとめられ、どのウィンドウがどのコンテナのものか分からなくなります。wintag はアイコンはまとめたまま、次のようにして見分けられるようにします。

- ウィンドウタイトルの先頭にコンテナ名を付けます。Dock のアイコンをクリックしたときのウィンドウ一覧や Alt+Tab で区別できます。
- アプリごとに Dock・アプリ一覧用のランチャーを 1 つ作ります。クリックすると、最後に使ったコンテナで起動します。

```
Dock: [rviz2]（1 つのアイコン）

  クリック → ウィンドウ一覧
    [whillLocalizer] localization2.rviz - RViz
    [20261002] example.rviz - RViz
```

## 動作環境

- GNOME（X11 セッション）
- bash 4.4 以上、python3、x11-utils、x11-xserver-utils、libxres1（パッケージの依存関係として自動で入ります）
- Docker
  - ログインユーザーが `sudo` なしで `docker` コマンドを使えること
  - コンテナ内のアプリがホストの X サーバーに表示できるよう設定されていること

## インストール

[Releases](https://github.com/MaeharaTakumi/wintag/releases) から `.deb` をダウンロードするか、ソースからビルドします。

```bash
./build.sh
```

```bash
sudo apt install ./wintag_2.2.0_all.deb
```

## ウィンドウ監視のオン・オフ

ウィンドウ監視は、インストール直後はオフです。オンにすると、すぐに監視が始まり、次回以降もログイン時に自動で始まります。

```bash
wintag on
```

```bash
wintag off
```

```bash
wintag status
```

オン・オフはユーザーごとの設定です（`~/.config/autostart/wintag-watch.desktop` の有無）。

## 使い方

| コマンド | 内容 |
| --- | --- |
| `wintag on` / `wintag off` | ウィンドウ監視をオン・オフする（既定はオフ） |
| `wintag status` | 監視の設定と実行状態を表示する |
| `wintag watch` | ウィンドウを監視する（`wintag on` で起動される。直接実行してもよい） |
| `wintag register [コマンド...]` | クリックしたウィンドウを手動で登録する |
| `wintag list` | 登録済みエントリの一覧を表示する |
| `wintag remove <エントリID>` | エントリを削除する |
| `wintag cleanup` | 削除済みコンテナのエントリをまとめて削除する |
| `wintag launch <エントリID>` | 登録済みアプリを起動する（Dock のアイコンから呼ばれる） |

### コンテナのアプリ

監視がオンなら、操作は不要です。コンテナでアプリのウィンドウが開くと、次のようになります。

- タイトルの先頭に `[コンテナ名]` が付きます。アプリがタイトルを変えても付け直します。
- 初めてのアプリ・コンテナの組み合わせなら自動で登録されます。

Dock のアイコンをクリックすると、最後に使ったコンテナで起動します。別のコンテナで起動するときは、`wintag list` でエントリ ID を確認して `wintag launch <エントリID>` を実行します。コンテナが停止していても、自動で起動してから実行します。

### ホストのアプリ・起動コマンドの変更

ホストのアプリは自動では登録されません。`register` を実行してからウィンドウをクリックすると登録されます。

```bash
wintag register
```

起動コマンドを指定すると、元のプロセスのコマンドの代わりにそのコマンドで起動するようになります。起動元を特定できないウィンドウは、コマンドを指定するとホストのアプリとして登録できます。

```bash
wintag register ros2 run rviz2 rviz2 -d /root/my.rviz
```

手動で登録したエントリは、その後の自動検出で上書きされません。

## 仕組み

- X サーバー（XRes 拡張）にウィンドウを作ったプロセスを問い合わせ、そのプロセスの cgroup から起動元のコンテナを判定します。`--net=host` のコンテナが複数あっても区別できます。
- X に TCP で接続しているなどでプロセスが分からない場合は、`WM_CLIENT_MACHINE` とホスト名が一致するコンテナが 1 つだけのときに限り判定します。
- タイトルは、ウィンドウごとに `_NET_WM_NAME` の変化を監視して付け直します。ウィンドウが閉じると監視も終わります。
- ランチャーはアプリ（WM_CLASS のクラス名）ごとに 1 つで、`StartupWMClass` で既存のウィンドウとまとめられます。
- アイコンはウィンドウ自身のアイコン（`_NET_WM_ICON`）から作ります。ない場合は汎用アイコンを使います。
- 登録時のコマンド・環境変数・作業ディレクトリ・ユーザーを保存し、起動時に再現します。

## データの保存先

| 場所 | 内容 |
| --- | --- |
| `~/.local/share/wintag/<エントリID>/` | 起動コマンド・環境変数・作業ディレクトリ・アイコンなど（アプリ×起動元ごと） |
| `~/.local/share/applications/wintag-<クラス名>.desktop` | Dock・アプリ一覧用のランチャー（アプリごと） |
| `~/.config/autostart/wintag-watch.desktop` | ログイン時の監視の自動起動（オンのときだけ） |

エントリ ID は `host-<クラス名>`（ホスト）または `<コンテナID先頭12桁>-<クラス名>`（コンテナ）です。

## 注意

- コンテナのアプリを起動するとき、`xhost +local:` を実行してローカルからの X 接続を許可します。
- 削除済みコンテナのエントリは、監視の開始時（ログイン時）に自動で片付けられます。
- 監視は 1 ユーザーにつき 1 つしか動きません。
- 監視をオフにしても、付けたタイトルはアプリが次にタイトルを変えるまで残ります。
- Dock から起動して失敗した場合（コンテナが削除されているなど）は、デスクトップ通知でお知らせします（`libnotify-bin` が必要）。

## 2.1.0 からの更新

2.2.0 から監視は既定でオフになり、更新すると全ユーザー向けの自動起動設定は削除されます。動いている古い監視を止めてから更新し、必要なら `wintag on` でオンにしてください。既存のエントリは自動で新しい形式に移行されます。

```bash
pkill -f '/usr/bin/wintag watch'
```

## アンインストール

先に監視をオフにしてから削除します。

```bash
wintag off
```

```bash
sudo apt remove wintag
```

ホームフォルダ内のデータは残ります。不要なら削除してください。

```bash
rm -rf ~/.local/share/wintag ~/.local/share/applications/wintag-*.desktop
```
